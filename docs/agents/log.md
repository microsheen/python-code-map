# log.md 的写法

`log.md` 是开发日志，也是**证据库**：下一轮的 agent 靠它知道上一轮量到了什么、什么还欠着。
所以格式与纪律比文采重要。一轮一节，纯追加。

## 读它

先取目录，别整读（文件已 1000+ 行）：

```powershell
Select-String -Path log.md -Pattern '^## '    # 轮次目录
Select-String -Path log.md -Pattern '遗留'     # 还欠着什么
Select-String -Path log.md -Pattern '不改写'   # 更正惯例的先例
```

## 轮次标题

```
## <日期> <这轮干了什么>（<关键判据> · <N 单测> · <M 项冒烟>）
```

标题里每个数字都来自实测输出，而且**最后写** —— 写完回头与正文核一遍。
标题停在早期估算值上是这个文件犯过次数最多的错（写过「431 单测」，实测 434）。

## 追加，不改写

历史轮次的读数不改。写错了就在新的一轮里更正，并写清错在哪、实测是多少：

```
- **更正上一轮记录里 N 处数字**（历史读数不改写，更正追加在这里）：① …… 实测是 **434**；② ……
```

先例：搜「上一轮记录不偷偷改写」与「历史读数……不改写」。行号会随追加漂移，用 grep 找，别引用行号。

## [实测] 与推断

- 量到的：`[实测] <日期>` + 读数 + 读数怎么来的（哪条命令、哪个 host、哪个 CI run）。
- 没量到的：明写是推断，或明写「本轮不可读」（例如 API 域名不通，CI 日志拿不到）。
- 「没读到」既不是通过也不是失败：先修观测点，再判断字节。

## 每轮该有的几段

1. 这轮改了什么、**没改**什么 —— 没改的那半要给判据（例如产物摘要与上一轮逐字相同）；
2. 门禁实测：typecheck / lint（error 与 warning 数）/ jest（suites 与 tests）/ smoke（passed/total）/ audit:egress；
3. CI：run id、逐 job 结论、deploy 是否按设计跳过；
4. 本轮学到的规矩，一句话，能被下一轮复用的那种；
5. 遗留：编号列出，能挂到票上就写票号。

## 与其他文件的分工

- 机制与平台行为 → `docs/ops-deployment.md`（log 只记「这一轮量到了什么」）。
- 决策与取舍 → `docs/adr/`（log 只记「这一轮按哪个 ADR 做的」）。
- 承重词定义 → `CONTEXT.md`。
- 判断类编码规则 → `CODING_STANDARDS.md`。
