# Python Code Map — Python 関数呼び出し関係図の可視化

[English](README.md) | [简体中文](README.zh-CN.md) | **日本語**

## デモ

**👉 今すぐ試す：<https://python-code-map.com>** — ページを開いて `.py` ファイルをいくつかドラッグ＆ドロップすると、呼び出し関係図がブラウザの中に描画されます。インストール不要、登録不要、アップロードも不要：解析はすべてあなた自身のブラウザ内で完結します。

> このドメインがあなたのネットワークから開けない場合、同じビルドが <https://python-code-map.pages.dev> でも配信されています。

_リポジトリ名・npm パッケージ名・IndexedDB のデータベース名はいずれも `code-map` のままです：前の 2 つは単なる識別子であり、最後を変えると既存ユーザーのローカルセッションが即座に復元不能になります。_

1 つ以上の `.py` ファイルをアップロードすると、関数呼び出し関係図がブラウザに表示されます — 左にコード、右にグラフ、どちら側をクリックしても反対側が該当位置に移動します。

- **純フロントエンド・ローカルファースト**：バックエンドサービスなし、アカウントなし、データベースなし、サードパーティのスクリプトやアナリティクスもなし。ソースコードはブラウザ内だけで解析され、アプリはあなたが要求していないリクエストを 1 件も出しません：ディスクから追加したファイルはこのマシン上に留まり、外向きの通信は**あなた自身が** URL から明示的にプルしたファイルだけです。証明できる主張は意図的に狭いままです — プルはあなたが入力した URL への GET のみ、リクエストボディは常に空、そして**あなたのコードの内容はどこにも送信されません**。かつてここにあった「送信はゼロ」という包括的な主張は [ADR-0006](docs/adr/0006-url-pull-egress.md) によって撤回されました；その背後のアサーションはそのまま残り、実ブラウザゲートがプル動作がないときに証明すべき**既定動作のベースライン**になっています。
- **セッションはあなた自身のマシン上にしか存在しない**：ファイル内容はブラウザのローカル IndexedDB（データベース `code-map` / ストア `session` / キー `current`）に書き込まれ、リロードで復元されます。Clear をクリックするかサイトデータを消去すれば完全に削除され、サーバがそれを見ることは永遠にありません。テーマの選択は localStorage の `code-map:theme` に保存されます（アプリ全体で唯一のキーです）が、これもこのマシンの外には出ません。
- **本物の構文解析**：Python は tree-sitter（WASM）で解析しており、正規表現で行をなでているのではありません — ネストした `def`、クラスのメソッド、`async def`、デコレータ、相対 import まで正しく認識します。
- **技術スタック**：Expo SDK 57 + React Native Web + react-native-svg + dagre レイアウト + zustand。

6 つの重要な設計判断は ADR に記録されています。コードを変更する前に読むことを推奨します：

- [ADR-0001 純フロントエンド + tree-sitter WASM、バックエンド／Pyodide は入れない](docs/adr/0001-expo-rn-web-no-backend.md)
- [ADR-0002 保守的な呼び出し解決と reason 分類](docs/adr/0002-conservative-call-resolution.md)
- [ADR-0003 フィードバック窓口は 2 本の href 以外の何ものにもならない](docs/adr/0003-feedback-channel-href-only.md)
- [ADR-0004 画面テーマは CSS カスタムプロパティで実装する（6 セット切替可能）](docs/adr/0004-css-variable-theming.md)
- [ADR-0005 グラフの 1 本の線がクリックできる — 集約エッジの「何番目の呼び出し」を順繰りに位置決め](docs/adr/0005-clickable-edges-call-site-cycling.md)
- [ADR-0006 「送信はゼロ」という包括的な主張を撤回 — 明示的な URL プルだけが唯一の外向きリクエスト](docs/adr/0006-url-pull-egress.md)

_ADR を含む `docs/` 配下はすべて中国語で書かれています。_

## クイックスタート

Node.js 18+ が必要です（20+ 推奨）。

```bash
npm install          # 依存関係のインストール（ネットワークが必要）
npm run web          # dev server を起動してブラウザを開く（既定は http://localhost:8081）
```

`npm install` の終了時に `postinstall`（つまり `npm run copy-wasm`）が自動的に実行されます：2 つの `.wasm` を node_modules から `public/wasm/` に同期し、Node 上で実スモークチェックを 1 回走らせます（`Parser.init` + `Language.load` + `parse`）。`[copy-wasm] 冒烟校验通过`（「スモークチェック合格」）が表示されれば、wasm の ABI は本当に一致しています。この 2 つの `.wasm` はコミットされていないため（`.gitignore` 参照）、**新しく clone したリポジトリでは必ず一度 `npm install` を実行してください**；`npm run web` / `npm run export` は `preweb` / `preexport` を通じて再度同期します。`--ignore-scripts` を付けてインストールした場合は、手動で `npm run copy-wasm` を実行してください。

続いて：「Select .py Files」をクリックしてアップロードするか、右側の領域にファイルを直接ドロップします。リポジトリにはすぐ試せるサンプルが入っています：`fixtures/main.py`、`fixtures/shapes.py`、`fixtures/utils.py`、`fixtures/multi.py`（1 本の線の背後にある 3 回の呼び出し）。

## 画面構成

```
┌─────────────────────────────────────── ツールバー ───────────────────────────────────────┐
│ アップロード ファイル chips（削除可） 範囲: 近傍/このファイル/全体 Theme  フィードバック │
│ 統計: 関数数 / 辺数 / 未解決数 + byReason    警告バー（不正ファイルの縮退）              │
├─────────────────────────────────────┬────────────────────────────────────────────────────┤
│  左：コード                         │  右：呼び出し関係グラフ                            │
│  ファイルタブ                       │  dagre 階層レイアウト（左から右）                  │
│  構文ハイライト + 行番号            │  ノードは所属ファイル色、バッジ=未解決数           │
│  関数名 / ƒ マーカーはクリック可能  │  ホイールズーム、ドラッグでパン、+ / − / 全体表示  │
└─────────────────────────────────────┴────────────────────────────────────────────────────┘
```

中央の仕切りはドラッグできます（左右比は 25%〜75% にクランプ）。ウィンドウ幅が 900px 未満になると自動的に上下スタックに切り替わります。

### 画面テーマ（6 セット切替可能）

トップバーの `Theme` ボタンは 6 行のパネルを開きます：`GitHub Dark`（既定）/ `GitHub Light` / `Dracula` / `Nord` / `Solarized Dark` / `Solarized Light`。各行は「3 つのプレビュー色ブロック + 公式の配色名 + 現在の項目にチェック印」で、行をクリックすると**その場で反映**されます — リロードも再アップロードも不要です。

- 仕組みは CSS カスタムプロパティです：`src/theme.ts` の `colors` / `tokenColors` / `FILE_COLORS` は形を変えず、値だけが `var(--cm-*)` の参照になったので、テーマの切り替えは `<html>` 上の 54 個の変数を書き換えるだけです。つまり **React の再レンダリングもファイルの再解析も起きず、構文ハイライトの分割も無効化されません** — ブラウザは追加のリクエストを 1 つも発行しません。
- 選択は localStorage の `code-map:theme` に保存されるため、リロード後も次の訪問後も維持されます。初回訪問は常に既定のダークテーマです（OS の設定は意図的に追いかけません）。Clear をクリックしてもテーマはリセット**されません** — 設定と解析対象のコードは別のものだからです。
- テーマで変わるのは配色と `color-scheme`（ブラウザ原生部品の明暗：スクロールバー、フォーム部品、キャレット）だけです。フォント、サイズ、間隔、角丸、レイアウト寸法、サイトアイコンは追随しません。
- すべてのパレットはその配色の公式公開 16 進値を使い、その後に WCAG コントラストゲートを通過します（本文色 ≥ 4.5、グラフィックとアクセント ≥ 3.0、`__tests__/theme.test.ts` で強制）。通らなければゲートは緩めず、そのパレットの値を調整します。
- エントリポイントは**意図的に `busy` でゲートしていません**。理由は `Feedback` と同じです：解析中や、ローカルストレージから古いセッションを復元している時こそ、人はまさにその画面を眺めているからです。
- パネルの `data-testid` アンカーが契約です：`topbar-theme` / `theme-panel` / `theme-option-<id>`。
- なぜこの道を選んだのか（CSP が止めるインライン boot script も、そのために残った 1 フレーム分の既定底色も含む）は [ADR-0004](docs/adr/0004-css-variable-theming.md) を参照してください。

## 双方向ナビゲーション（核心機能）

**グラフ → コード**：グラフ内の任意の関数ノードをクリックすると、左側が

1. その関数が属するファイルのタブに切り替わり、
2. その `def` 行までスクロールし、
3. 関数本体全体（`startLine..endLine`）をハイライト帯で覆って一度フラッシュさせ、
4. 右側のグラフをその関数の近傍（自分 + 直接の呼び出し元／呼び出し先）にクリップします。

**コード → グラフ**：コード内の関数をクリックすると、右側が

1. スコープ済みサブグラフとそのレイアウトを再計算し、
2. そのノードをビューポート中央に移動させ（現在のズーム倍率は維持）、
3. そのノードと直接の呼び出しエッジをハイライトし、他のすべてのノード／エッジを減光します。

コード内のクリックは**意味を考慮したもの**で、単なる「クリックした行を選択」ではありません：

- 関数名（`def boot` の `boot`）や行番号横の `ƒ` マーカーをクリック → その関数を選択；
- 関数本体の中の任意の行をクリック → **最も内側**の関数を選択（`def` がネストしていても外側を誤選択しません）；
- **呼び出し箇所**（`utils.load_config(...)` の名前）をクリック → **呼び出し先**、つまりそのエッジの反対側を選択 — ファイルをまたぐ場合はそのまま他ファイルの関数にジャンプします。

同じ関数を再度クリックすると、位置決めアニメーションが再トリガーされます（`selection.nonce` をインクリメントして実装；そうしないと id が変わらず、React が「何もすることがない」と判断してしまいます）。

### 線を 1 本クリック：集約エッジの背後にある N 個の呼び出し箇所

ノードは関数ですが、エッジは**集約**です — A が B を呼ぶ回数はすべて 1 本のポリラインに統合され、線の
太さは回数に従います（ADR-0002）。個々の呼び出し箇所はそのエッジの中にそのまま残っているため、
**線そのものもクリックできます**：

- **線をクリック** → コード領域が caller の属するファイルに切り替わり、**1 個目**の呼び出し箇所までスクロール
  し、その 1 行だけをフラッシュさせ、このエッジの**すべての**呼び出し箇所に印を付けます：現在のものでない
  箇所には下線、現在の箇所には背景帯 + 番号チップ。チップは**行番号の左**（sticky な行番号槽の中、`ƒ` と
  同じ枠で呼び出し箇所が優先）に置かれるので、行を横にスクロールしてもチップは行番号と一緒に画面の左に
  残ります — コンテンツ座標のオーバーレイでは行番号から滑り去ってしまうからです。
- **同じ線をもう一度クリック** → 2 個目、3 個目、最後まではいくと**1 個目に巻き戻ります**。`Shift`+クリックは
  同じサイクルを逆向きに歩みます。まだ印の付いていないエッジをクリックした場合は常に 1 個目から始まります —
  「現在」がなければ「戻る」もありません。
- **`‹ 2/3 ›`** ステッパはコード領域の右下隅。細い線を追いかける必要がなく、`✕` で解除します。
- **呼び出し箇所が 1 個だけの線も、家具はひとつ減りません**：ステッパはそこにあり `1/1` と読め、その 1 箇所には
  印が付き、行番号の左にチップが座ります — 描画されないのは 2 本の矢印だけ、行く先がないからです。フッターは
  引き続き `file:line` だけ（あの一文に `1/1` を足してもノイズです）。この項目はリリース当日は「何も敷かない」
  作りにして翌日ユーザーの好みで差し戻しました — 両方のトレードオフは
  [ADR-0005 §9](docs/adr/0005-clickable-edges-call-site-cycling.md) に残しています。
- **グラフのフッター**が現在の位置を告げます：`caller → callee · 2/3 · multi.py:7`（1 個だけなら `· 2/3` は出ません）。
- **ホバー**：カーソルが pointer に変わり、クリックでどこに着くかをツールチップが予告します
  （`caller → callee · 3 call sites · first at line 6`）。エッジ数が 1500 を超えるとホバーのヒットテストは自動的に
  オフになります（大きなグラフの滑らかさを保つため）が、クリックは影響を受けません。
- **逆向きも同じ線を光らせます**：コードの中で呼び出し箇所をクリックすると、そのエッジが `origin: 'code'` で
  選択されます — コードはもう目の前にあるので、この経路はスクロールもフラッシュもしません。

これらの「何番目」の順序はたった 1 か所、`src/graph/edges.ts` の `compareCallSites`（行番号 → 同じ行内では列 →
最後に原文でタイブレーク）にしか存在しません。だからチップ・ステッパ・フッター・テストが言う「3 個のうち
2 個目」はいつも同じ意味です。さらにパーサの不変条件がこの機能を実現可能にしています：**1 つのエッジの
呼び出し箇所は必ず同一ファイルにある** — caller は 1 つのファイルにしか定義できないので、その呼び出し箇所も
当然そのファイルの中にあり、コード領域はファイルをまたぐグループ化をする必要がありません。

線をクリックしても**他に何も変わりません**：選択・範囲・ナビゲーション履歴・ズーム／パンは一切動かず、
リクエストもゼロ。「どの線を見ているか」と「どの関数を見ているか」は別の軸なので、3 回の呼び出しを 1 つずつ
見る作業が、あなたがクリップ済みの近傍を吹き飛ばすはずがありません。実際の選択変化（ノードクリック、
コードクリック、範囲切り替え、戻る／進む、ファイル削除、再パース、Clear）はすべて印を消し、グラフの空白
クリックも同じく消します。

線のヒット判定は、その線を描くのと同じサンプル点列を使い、**画面の** 7 ピクセル（`EDGE_HIT_TOL`、現在のズームで
割るので拡大縮小しても手触りが一定）を許容範囲とします。ノードは常にその下を通る線より優先です。
`data-testid` アンカーが契約です：グラフ側は `graph-edge-<src>-><tgt>` / `graph-edge-tooltip` / `graph-edge-info`、
コード側は `callsite-stepper` / `callsite-prev` / `callsite-count` / `callsite-next` / `callsite-clear` /
`callsite-mark-<i>` / `callsite-mark-active`。回数で分岐するのは**矢印 2 本だけ**です：呼び出し箇所が 1 個の
とき `callsite-prev` / `callsite-next` は存在しませんが、上の id は他すべて存在します。`callsite-mark-active` は
オーバーレイではなくその行の sticky な行番号槽の中に描画されるので `style.left` は常に空文字、位置は矩形でしか
測れず、しかも「その行の左縁からの距離」で比較する必要があります — 絶対スクリーン座標はパンで流れます。
平行エッジでも、一覧を出すのでも、1 個目にだけ飛ぶのでも、線の上に ①②③ を貼るのでもなく
「循環」にした理由：[ADR-0005](docs/adr/0005-clickable-edges-call-site-cycling.md)。

## フィードバック窓口

トップバーの `Feedback` は読み取り専用のパネルを開きます。**ページが外に公開するリンクはちょうど 2 本**：GitHub Issues とメールエイリアスで、どちらも素の `<a href>` です — クリックしたときにだけ何かが起きます。`fetch` なし、beacon なし、`<form>` なし、`window.open` なし、クリップボード書き込みもなし。理由はこうです：フィードバックはこのサイト全体で唯一「情報を外へ持ち出したい」と本質的に望む機能であり、したがって「あなたのコードの内容はどこにも送信されない」という約束に対する唯一の実質的な反例リスクになります。だからこそ「このページは物理的に何も送信できない」という形で作ってあります。

| 窓口            | プライバシー | 備考                                                                                                                       |
| --------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------- |
| GitHub Issues   | **公開**     | 第一の窓口：議論可能で追跡可能、同じ問題に対する他の人の報告も見えます                                                     |
| メールエイリアス | 非公開       | 純粋な転送ルール；**返信は個人メールボックスから届き、このアドレスからは届きません**。現在はゲートで無効化されており、有効化されるまでパネルにこの行は描画されません |

パネル下部の編集可能な診断ブロックは **8 フィールドのホワイトリスト、件数のみ**で、順序は固定です：

```
build / ua / files / funcs / edges / unresolved / warnings / persisted
```

- ファイル名も関数名もソーステキストも入りません：配列は長さだけを寄与し、それ以外の型はすべて `0` に縮退するため、それらの情報は**構造的に入り込むことができません**（`__tests__/feedback.test.tsx` がカナリアで固定しています）。
- `build` は、現在実行中のエントリスクリプトの名前に入っているハッシュの**先頭 8 文字**です（`npm run web` の dev バンドルにはハッシュが付かないため、そこで `unknown` になるのは想定内で、不具合ではありません）。意図的に 8 文字 — 運用ドキュメント §4 の「32 桁 16 進の完全な id は絶対にファイルに入れない」ルールを参照。
- `ua` は 160 文字で切り詰められ、全体の予算は 600 文字です；予算を超過したときには `ua` の末尾だけが犠牲になり、フィールド全体が失われることはありません。
- このテキストは自由に編集・削除できます：一度編集すると、**2 本のリンクはどちらもあなたの編集版を運びます**。閉じて開き直すと下書きは破棄され、自動計測値が再サンプリングされます。

3 つのゲートが、この段落をレビュアの注意力に頼るのではなく事実に変えます：

1. `npm run audit:egress`（CI の `checks` ジョブのブロッキングステップ）は `src/feedback/contact.ts`、`src/components/FeedbackDialog.tsx`、`src/platform/web/buildStamp.ts` を逐語的に読みます：リクエストプリミティブ（`fetch(` / `<form` / `new Image(` / `navigator.clipboard` …）や未公開のメールリテラルが 1 つでもあれば赤になります — 素のテキストマッチングなので**コメントもカウントされます**。
2. jest のカナリア：目立つ秘密情報を詰め込んだ診断ソースを流し込み、それらが 3 つの出力（テキスト、Issues の href、mailto）のどこにも現れないことをアサートします。
3. スモーク G1〜G6：実ヘッドレス Chrome で「開く → 閉じる」の完全な 1 往復を行い、**リクエスト数が 1 件も増えていないこと**、そしてパネルが本当に最前面に浮かんでいること（閉じるボタン中心のヒットテストがボタン自身を返すこと）をアサートします。

パネルの `data-testid` アンカーが契約です。1 つでもリネームしたら契約変更になります（スモークスクリプトとこのドキュメントを同時に直す必要があります）：
`feedback-dialog` / `feedback-intro` / `feedback-lines` / `feedback-email-label` / `feedback-email` /
`feedback-mail-link` / `feedback-issues-link` / `feedback-diag-label` / `feedback-diag` /
`feedback-hint` / `feedback-close`、そして入口ボタンは `topbar-feedback`。

入口は**意図的に `busy` でゲートしていません**：解析中も、ローカル IndexedDB から古いセッションを復元している間もクリック可能でなければなりません — 復元されたその古い版を眺めている人こそ、バグを報告する必要性が最も高い人です。

エイリアスは現在 `CONTACT_EMAIL = null` によってゲートで無効化されています（Email Routing が有効化されていないため）。8 ステップの有効化ランブック（「本当にテストメールを送って到達を確認しなければならない — コンソールに verified と表示されるのは証拠ではない」を含む）は [docs/ops-deployment.md](docs/ops-deployment.md) の §9 に、なぜ 2 本の href という形なのかは [ADR-0003](docs/adr/0003-feedback-channel-href-only.md) にあります。

## ブラウザ自動化受け入れ（実 Chrome + CDP）

jest + jsdom では「フラッシュするハイライトが実 rAF でフェードアウトするか」や「SVG ノードが実マウスで本当にヒットできるか」といった問題は捕捉できません（コミット `d0f0832` が直したのはまさにそのようなブラウザ限定のバグでした）。そこで 2 つ目の、実ブラウザのスクリプトがあります：ヘッドレス Chrome + ネイティブ CDP プロトコルで、**playwright / puppeteer に依存しません** — ローカルに Chrome か Chromium が入っていれば実行できます。

```bash
npm run export                  # まず dist/ を生成
node scripts/browser-verify.mjs # 75 アサーション（うち 16 は E/F/G のベースラインと契約、22 はエッジ → 呼び出し箇所）；すべて緑 => 終了コード 0
```

スクリプトは `dist/` 用の静的サーバを自分で起動し、`dist/_headers` のルールをすべてのレスポンスに逐語的に適用します（つまりスモークテストは本番の CSP そのもので走ります）。ポートが使用中のときは既存サービスを再利用しますが、その前に 2 つを検証します：そのポートで動いているものが本当にこのアプリケーションであること（判定基準は HTML 内のこのプロジェクトの Metro エントリスクリプトタグであって **`<title>` ではない** — タイトルを変えた途端に誤判定するからです）、そして配信されているバイト列が `dist/index.html` と完全一致すること。その後ヘッドレス Chrome を起動し、`fixtures/` の 4 ファイルを流し込み、**実マウスイベントで** SVG ノードと SVG エッジとコードトークンをクリックして、項目ごとにアサートします：

| グループ                  | カバー範囲                                                                                                                                     |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Upload                    | 赤い致命エラーバーがない；グラフが描画される（4 つの fixture のベースライン 47 ノード / 50 エッジ）                                                             |
| A グラフ → コード         | ファイルが切り替わり、`def` 行が完全に見える位置までスクロールし、ハイライト帯が `def` 行に乗る；フラッシュが出現 → ピーク → フェード → アンマウント；連打で再トリガー |
| B コード → グラフ         | 対象ノードが中央に来る（ずれ < 40px）かつ stroke が太くなる；コード → グラフ方向ではフラッシュ**しない**                                        |
| C ファイル横断の深いジャンプ | `shapes.py` から `utils.py:95` へ飛ぶ；スクロール量、ハイライト帯の位置、フラッシュがすべて正しい                                            |
| D 意味的クリック          | 呼び出し箇所をクリックすると呼び出し先が選択される；本体の中間行をクリックするとそれを包む関数が選択される                                      |
| I エッジ → 呼び出し箇所      | `multi.py` の集約ポリライン `caller → callee` を実マウスでクリック：ファイル切り替え、1/3 → 2/3 → 3/3 → 1/3 の循環、`Shift` で逆向き、3 箇所にすべて印が付いて x が厳密に増加、番号チップが実測で**行番号の左**（その行の左縁から 5..19px）に座ること、`‹ ›` ステッパと `✕`、呼び出し箇所が 1 個だけの線も**同じ家具を全部出す**（`1/1` と読めるステッパ、ただし矢印 2 本は描画されず、その 1 箇所に印と行番号の左のチップ）で、ちゃんと 54 行目にスクロールしてフラッシュすること、ホバーのツールチップと pointer カーソル、そしてこのグループ全体で**リクエストが 1 件も増えない** |
| 安定性                    | コンソールエラーなし、未捕捉のページ例外なし                                                                                                   |
| S 成果物の同一性          | 配信バイト列 == `dist/index.html` のバイト列（sha256 一致）；レスポンスヘッダが本当に `_headers` の CSP を運んでいる；成果物 HTML に絶対 URL がゼロ |

## サイトアイコン

`public/icon.svg` が唯一の真実の源です：明るい紙の背景 + 抽象化されたコードグラフ — 青/黄/緑/紫（テーマのファイル色）の塗りつぶし角丸ノード 4 つを、テーマのアクセント色の太い丸端ストローク 3 本で結んだもの（旧「ノード + リンク」の骨格は保ち、グリッド、グロー、矢印、内部線は落としました）。`npm run icons` がこれを実 Chrome でラスタライズし、`favicon.ico`（16/32/48、PNG-in-ICO）、`apple-touch-icon.png`（180）、`icon-192.png`、`icon-512.png` を生成します — **すべてコミット済み**なので、export と CI の checks ジョブはブラウザなしで完全な `dist/` を作れます。`npm run export` の postexport ステップはまず `scripts/inject-html-head.mjs` を実行し、成果物 HTML の `<head>` に 4 つの `<link>` と 2 つの `<meta>` を書き込みます（同一オリジンの相対パス；冪等性のセンチネルは `data-codemap="icon"` なので、繰り返し実行してもタグが重なりません）。続いて `polish-dist.mjs` が自己チェックを行います — 注入された href も「絶対 URL ゼロ」ゲートの対象内であり、ゲートの外にある飛地ではありません。アイコンの色は `src/theme.ts` からしか取れず、許可されるのは**既定**テーマの色値だけです（`__tests__/icons.test.ts` がこの不変条件をロックしている）。UI には 6 つのテーマがありますが、アイコンとブランドカラーにはテーマがありません：テーマを切り替えてもアイコンは**動かず**（ブランドは固定）、追随するのはアドレスバーの `theme-color` だけです。ヘッドレス Chrome は `<link rel="icon">` を取得しないため、スモークテストは注入されたすべての href を `<img>` 経由で能動的に引きます（グループ F）。そしてそれらのリクエストはグループ E のベースラインのアサーション E1/E2/E4/E5 も通ります。

## 解析能力と限界

**エッジが描かれるもの**：ファイル内の直接呼び出し、ファイルをまたぐ `mod.func()` 呼び出し、`from m import f` の後の素の `f()`、`as` エイリアス付き import、相対 import、`self.method()` / `cls.method()`、`Cls.staticmethod()`、インスタンス化 `Cls(...)` → `__init__`、ネストした関数がそれを包む関数を呼ぶケース、再帰の自己ループ。

**エッジが付かない呼び出し箇所**は reason（`ambiguous` / `external` / `dynamic` / `unknown`）付きで記録され、UI 上はノードのバッジと上部の統計として表面化します。完全なルール、根拠、却下された代替案は [ADR-0002](docs/adr/0002-conservative-call-resolution.md) にあります。

その他の限界：

- 受け付けるのは `.py` / `.pyi` のテキストファイルのみ；1 ファイルあたり 1MB が上限で、超過分はスキップとして報告されます。
- 永続化はあなた自身のブラウザの中だけで起きます：セッション（全ファイル内容を含む）はローカル IndexedDB に書き込まれ、リロードで復元されます。サーバ側の保存はなく、サイトデータの消去が完全な削除です。
- 解析はブラウザのメインスレッド上でバッチ実行されます（1 バッチ 3 ファイル）— 数十ファイルなら瞬時に感じられますが、数千ファイルのリポジトリでは固まります。Web Worker は予約済みだがまだ有効化されていない最適化スロットです。
- 静的な構文解析のみ；アップロードされたコードは一切実行されません。

## テスト

3 層あり、すべて `npm test` で走ります：

| 層                             | ファイル                                                                                                                             | wasm が必要？                            |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------- |
| **純関数の単体テスト**         | `modules` / `imports` / `scope` / `layout` / `buildGraph` / `edges` / `store` / `clickRanges` / `graphPaneMath` / `codeView` / `smoke` / `theme`（パレット構造 + 変数の閉包 + WCAG ゲート）           | 不要（`treeLike` インターフェース経由の偽の構文木；`edges` は手作りグラフでも走る） |
| **コンポーネントとインタラクション** | `appFlow.test.tsx` / `topBar.test.ts` / `feedback.test.tsx`（カナリア + ホワイトリスト形状 + パネル描画） / `themePicker.test.tsx`（テーマパネルと切り替え）                        | 不要（store を事前に投入）               |
| **実 wasm フルチェーン**       | `parser.wasm.test.ts` / `imports.wasm.test.ts` / `e2e.wasm.test.tsx`                                                                  | 必要                                     |

`public/wasm/*.wasm` が存在しない場合、第 3 層は失敗するのではなく**丸ごとスキップ**されます（`describeWasm` ヘルパ）。したがって `--ignore-scripts` でインストールした場合でも、最初の 2 層は実行できます。すべてを走らせるには：先に `npm run copy-wasm`（通常の `npm install` は `postinstall` で既にやっています）。

`e2e.wasm.test.tsx` が実際の使用に最も近いものです：実 wasm が fixtures を解析 → `store.loadFiles` → `AppRoot` を描画 → 実際のクリック、という流れで、上記受け入れチェックリストの 2 つの核心ナビゲーション経路、不正ファイルの縮退、ファイル削除の同期をカバーします。

解析ルールを変更するときは、`__tests__/parser.wasm.test.ts` が読み込む 3 ファイルの統計ベースライン（funcs 45 / edges 49 / unresolved 26）に注意してください。数字が動いたら、なぜ動いたのかを説明できなければなりません — テストを編集して済ませないこと。`fixtures/multi.py`（クリックできる線のために追加）と `fixtures/broken.py` は意図的にこのベースラインの外です；実ブラウザのスモークで 4 つの fixture が 47 ノード / 50 エッジになるのはまさに `multi.py` が増える分です。

`npm test` の外に第 4 の層があります：実ブラウザ受け入れ（`node scripts/browser-verify.mjs`、`npm test` には含まれません）。実 Chrome + rAF + ネイティブマウスイベント上で走り、jsdom では扱えないフラッシュのフェードアウトと SVG のヒットテストをカバーします；「ブラウザ自動化受け入れ」のセクションを参照。

## トラブルシューティング

**`[copy-wasm] 冒烟校验失败`（スモークチェック失敗）/ ページ上部の赤いエラーバー**

最も可能性が高いのは `web-tree-sitter` と言語 wasm の ABI が一致していないことです。両パッケージは `package.json` で完全固定されています（`web-tree-sitter` `0.27.0` + `@vscode/tree-sitter-wasm` `0.3.1`）；片方だけをアップグレードしないでください。アップグレード後は必ず `npm run copy-wasm` を再実行し、スモークチェックが通ることを確認してください。赤いエラーバーは `Language.load` が投げたエラーを逐語的に表示します — サイレントな縮退はありません。

**ページは開くがグラフが空 / `LinkError`**

`public/wasm/` の下に本当に 2 つの `.wasm` があるか確認してください。dev server も `expo export` も `public/` を同梱するので、パスは `/wasm/tree-sitter.wasm` です。

**ホイールでズームするとページ全体がスクロールする**

wheel リスナは `preventDefault` できるように**非パッシブ**（`passive: false`）でなければなりません。react-native-web の `onWheel` はそれができないため、`src/platform/web/domEvents.ts` で自前にネイティブイベントを購読しています。これを RN の `onWheel` に戻さないでください。

**`npm run export` が制限された環境で EPERM を報告する**

Expo はユーザーディレクトリに状態ファイルを書きます（`~/.expo/state.json`）。その書き込みがサンドボックス化されている環境では、`EXPO_HOME` をリポジトリ内に向けてください：

```powershell
$env:EXPO_NO_TELEMETRY = "1"; $env:CI = "1"; $env:EXPO_HOME = "$PWD\.expo-home"
npx expo export --platform web --output-dir dist
```

## リリースと運用

完全な手順、プラットフォームの落とし穴、ロールバック手順は [docs/ops-deployment.md](docs/ops-deployment.md) に記録されています。最も一般的な 2 つの操作：

- **公開を止める**：リポジトリ変数 `DEPLOY_ENABLED` を `false` に設定する。これが唯一のスイッチです — コードは消さず、ジョブは消さず、認証情報も消しません。
- **本番がまさにテストしたあのビルドだと確認する**：`npm run export` は最後に `dist/index.html` の sha256 を表示します；スモークテストの `S1` アサーションがサーバのバイト列を比較し、`check-deploy.mjs --dist=dist` が本番とローカル成果物を比較します。
