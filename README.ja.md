# Python Code Map — Python 関数呼び出し関係図の可視化

[English](README.md) | [简体中文](README.zh-CN.md) | **日本語**

## デモ

**👉 今すぐ試す：<https://python-code-map.com>** — ページを開いて `.py` ファイルをいくつかドラッグ＆ドロップすると、呼び出し関係図がブラウザの中に描画されます。インストール不要、登録不要、アップロードも不要：解析はすべてあなた自身のブラウザ内で完結します。

> このドメインがあなたのネットワークから開けない場合、同じビルドが <https://python-code-map.pages.dev> でも配信されています。

_リポジトリ名・npm パッケージ名・IndexedDB のデータベース名はいずれも `code-map` のままです：前の 2 つは単なる識別子であり、最後を変えると既存ユーザーのローカルセッションが即座に復元不能になります。_

1 つ以上の `.py` ファイルをアップロードすると、関数呼び出し関係図がブラウザに表示されます — 左にコード、右にグラフ、どちら側をクリックしても反対側が該当位置に移動します。

- **純フロントエンド・送信ゼロ**：バックエンドサービスなし、アカウントなし、データベースなし、サードパーティのスクリプトやアナリティクスもなし。ソースコードはブラウザ内だけで解析され、いかなるリクエストの一部としてもこのマシンの外に出ません — これはスローガンではなく、実ブラウザゲートの中の 1 行ずつのアサーションです（すべてのリクエストが同一オリジン、すべて GET、リクエストボディは空、URL にあなたのファイル名やコード断片は含まれない）。
- **セッションはあなた自身のマシン上にしか存在しない**：ファイル内容はブラウザのローカル IndexedDB（データベース `code-map` / ストア `session` / キー `current`）に書き込まれ、リロードで復元されます。Clear をクリックするかサイトデータを消去すれば完全に削除され、サーバがそれを見ることは永遠にありません。
- **本物の構文解析**：Python は tree-sitter（WASM）で解析しており、正規表現で行をなでているのではありません — ネストした `def`、クラスのメソッド、`async def`、デコレータ、相対 import まで正しく認識します。
- **技術スタック**：Expo SDK 57 + React Native Web + react-native-svg + dagre レイアウト + zustand。

3 つの重要な設計判断は ADR に記録されています。コードを変更する前に読むことを推奨します：

- [ADR-0001 純フロントエンド + tree-sitter WASM、バックエンド／Pyodide は入れない](docs/adr/0001-expo-rn-web-no-backend.md)
- [ADR-0002 保守的な呼び出し解決と reason 分類](docs/adr/0002-conservative-call-resolution.md)
- [ADR-0003 フィードバック窓口は 2 本の href 以外の何ものにもならない](docs/adr/0003-feedback-channel-href-only.md)

_ADR を含む `docs/` 配下はすべて中国語で書かれています。_

## クイックスタート

Node.js 18+ が必要です（20+ 推奨）。

```bash
npm install          # 依存関係のインストール（ネットワークが必要）
npm run web          # dev server を起動してブラウザを開く（既定は http://localhost:8081）
```

`npm install` の終了時に `postinstall`（つまり `npm run copy-wasm`）が自動的に実行されます：2 つの `.wasm` を node_modules から `public/wasm/` に同期し、Node 上で実スモークチェックを 1 回走らせます（`Parser.init` + `Language.load` + `parse`）。`[copy-wasm] 冒烟校验通过`（「スモークチェック合格」）が表示されれば、wasm の ABI は本当に一致しています。この 2 つの `.wasm` はコミットされていないため（`.gitignore` 参照）、**新しく clone したリポジトリでは必ず一度 `npm install` を実行してください**；`npm run web` / `npm run export` は `preweb` / `preexport` を通じて再度同期します。`--ignore-scripts` を付けてインストールした場合は、手動で `npm run copy-wasm` を実行してください。

続いて：「Select .py Files」をクリックしてアップロードするか、右側の領域にファイルを直接ドロップします。リポジトリにはすぐ試せるサンプルが入っています：`fixtures/main.py`、`fixtures/shapes.py`、`fixtures/utils.py`。

## 双方向ナビゲーション（核心機能）

**グラフ → コード**：グラフ内の任意の関数ノードをクリックすると、左側が

1. その関数が属するファイルのタブに切り替わり、
2. その `def` 行までスクロールし、
3. 関数本体全体（`startLine..endLine`）をハイライト帯で覆って一度フラッシュさせ、
4. 右側のグラフをその関数の近傍（自分 + 直接の呼び出し元／呼び出し先）にクリップします。

**コード → グラフ**：コード内の関数をクリックすると、右側が

1. スコープ済みサブグラフとそのレイアウトを再計算し、
2. そのノードをビューポート中央に移動させ（現在のズーム倍率は維持）、
3. そのノードと直接の呼び出しエッジをハイライトし、他のすべてのノード／エッジを減光します。

コード内のクリックは**意味を考慮したもの**で、単なる「クリックした行を選択」ではありません：

- 関数名（`def boot` の `boot`）や行番号横の `ƒ` マーカーをクリック → その関数を選択；
- 関数本体の中の任意の行をクリック → **最も内側**の関数を選択（`def` がネストしていても外側を誤選択しません）；
- **呼び出し箇所**（`utils.load_config(...)` の名前）をクリック → **呼び出し先**、つまりそのエッジの反対側を選択 — ファイルをまたぐ場合はそのまま他ファイルの関数にジャンプします。

同じ関数を再度クリックすると、位置決めアニメーションが再トリガーされます（`selection.nonce` をインクリメントして実装；そうしないと id が変わらず、React が「何もすることがない」と判断してしまいます）。

## フィードバック窓口

トップバーの `Feedback` は読み取り専用のパネルを開きます。**ページが外に公開するリンクはちょうど 2 本**：GitHub Issues とメールエイリアスで、どちらも素の `<a href>` です — クリックしたときにだけ何かが起きます。`fetch` なし、beacon なし、`<form>` なし、`window.open` なし、クリップボード書き込みもなし。理由はこうです：フィードバックはこのサイト全体で唯一「情報を外へ持ち出したい」と本質的に望む機能であり、したがって「あなたのソースコードは上流に行かない」という約束に対する唯一の実質的な反例リスクになります。だからこそ「このページは物理的に何も送信できない」という形で作ってあります。

| 窓口            | プライバシー | 備考                                                                                                                       |
| --------------- | ------------ | -------------------------------------------------------------------------------------------------------------------------- |
| GitHub Issues   | **公開**     | 第一の窓口：議論可能で追跡可能、同じ問題に対する他の人の報告も見えます                                                     |
| メールエイリアス | 非公開       | 純粋な転送ルール；**返信は個人メールボックスから届き、このアドレスからは届きません**。現在はゲートで無効化されており、有効化されるまでパネルにこの行は描画されません |

パネル下部の編集可能な診断ブロックは **8 フィールドのホワイトリスト、件数のみ**で、順序は固定です：

```
build / ua / files / funcs / edges / unresolved / warnings / persisted
```

- ファイル名も関数名もソーステキストも入りません：配列は長さだけを寄与し、それ以外の型はすべて `0` に縮退するため、それらの情報は**構造的に入り込むことができません**（`__tests__/feedback.test.tsx` がカナリアで固定しています）。
- `build` は、現在実行中のエントリスクリプトの名前に入っているハッシュの**先頭 8 文字**です（`npm run web` の dev バンドルにはハッシュが付かないため、そこで `unknown` になるのは想定内で、不具合ではありません）。意図的に 8 文字 — 運用ドキュメント §4 の「32 桁 16 進の完全な id は絶対にファイルに入れない」ルールを参照。
- `ua` は 160 文字で切り詰められ、全体の予算は 600 文字です；予算を超過したときには `ua` の末尾だけが犠牲になり、フィールド全体が失われることはありません。
- このテキストは自由に編集・削除できます：一度編集すると、**2 本のリンクはどちらもあなたの編集版を運びます**。閉じて開き直すと下書きは破棄され、自動計測値が再サンプリングされます。

3 つのゲートが、この段落をレビュアの注意力に頼るのではなく事実に変えます：

1. `npm run audit:egress`（CI の `checks` ジョブのブロッキングステップ）は `src/feedback/contact.ts`、`src/components/FeedbackDialog.tsx`、`src/platform/web/buildStamp.ts` を逐語的に読みます：リクエストプリミティブ（`fetch(` / `<form` / `new Image(` / `navigator.clipboard` …）や未公開のメールリテラルが 1 つでもあれば赤になります — 素のテキストマッチングなので**コメントもカウントされます**。
2. jest のカナリア：目立つ秘密情報を詰め込んだ診断ソースを流し込み、それらが 3 つの出力（テキスト、Issues の href、mailto）のどこにも現れないことをアサートします。
3. スモーク G1〜G6：実ヘッドレス Chrome で「開く → 閉じる」の完全な 1 往復を行い、**リクエスト数が 1 件も増えていないこと**、そしてパネルが本当に最前面に浮かんでいること（閉じるボタン中心のヒットテストがボタン自身を返すこと）をアサートします。

パネルの `data-testid` アンカーが契約です。1 つでもリネームしたら契約変更になります（スモークスクリプトとこのドキュメントを同時に直す必要があります）：
`feedback-dialog` / `feedback-intro` / `feedback-lines` / `feedback-email-label` / `feedback-email` /
`feedback-mail-link` / `feedback-issues-link` / `feedback-diag-label` / `feedback-diag` /
`feedback-hint` / `feedback-close`、そして入口ボタンは `topbar-feedback`。

入口は**意図的に `busy` でゲートしていません**：解析中も、ローカル IndexedDB から古いセッションを復元している間もクリック可能でなければなりません — 復元されたその古い版を眺めている人こそ、バグを報告する必要性が最も高い人です。

エイリアスは現在 `CONTACT_EMAIL = null` によってゲートで無効化されています（Email Routing が有効化されていないため）。8 ステップの有効化ランブック（「本当にテストメールを送って到達を確認しなければならない — コンソールに verified と表示されるのは証拠ではない」を含む）は [docs/ops-deployment.md](docs/ops-deployment.md) の §9 に、なぜ 2 本の href という形なのかは [ADR-0003](docs/adr/0003-feedback-channel-href-only.md) にあります。

```bash

```

- [ ] 上部のステータスが解析完了を示し、おおむね **funcs 45 / edges 47 / unresolved 28**
      （`ambiguous 1 / external 14 / dynamic 13 / unknown 0`）— ADR-0002 のベースラインと一致
- [ ] 右に呼び出し関係図が表示され、ノードがファイルごとに色分けされ、下部にファイル色の凡例がある
- [ ] ファイルをまたぐエッジが見える：`main.py::boot → utils.py::load_config`
- [ ] 再帰の自己ループが見える：`main.py::factorial` が自分自身を指す
- [ ] **グラフ → コード**：`utils.py::load_config` ノードをクリック → 左が utils.py に切り替わり、52 行目までスクロールし、
      関数本体にハイライト帯が付く
- [ ] **コード → グラフ**：main.py の 22 行目の関数名（`def boot():`）をクリック → 右が `boot` を中央に置いてハイライトする
- [ ] **呼び出し箇所ジャンプ**：main.py の 24 行目 `cfg = utils.load_config(...)` の中の名前をクリック →
      選択されるのは `utils.py::load_config`（呼び出し先）であって、`boot` ではない
- [ ] ズーム＆パン：ホイールはカーソル位置を基準にズームし、空白のドラッグはパン、`+` / `−` / Fit View もすべて動作する
- [ ] 範囲切り替え：Neighborhood / This File / All がすべて切り替わり、「All」でノードが多いときには上部に大規模グラフの注意書きが出る
- [ ] 単一ファイルの削除：`utils.py` チップの × をクリック → そのノードとファイル横断エッジが一緒に消え、
      左のファイルタブも同期して削除され、削除したファイルを指していた現在の選択はクリアされる
- [ ] エラー隔離：`fixtures/broken.py`（意図的な構文エラー）もアップロード → 上部の黄色い警告バーが broken.py を名指しし、
      他の 3 ファイルは描画され続け、フロー全体はクラッシュしない
- [ ] 大きなファイルでのスムーズスクロール：数千行のファイルをアップロードし、コード領域を素早くスクロールしてもフレーム落ちしない
      （コード領域はウィンドウ化されており、可視範囲 ± 24 行だけをペイントします）
- [ ] トップバーの `Feedback`：**解析が進行中でもクリック可能**（読み取り専用の入口であり、意図的に busy でゲートしていない）；
      パネルの診断ブロックはちょうど 8 行の件数（dev では `build` が `unknown` になる — Metro のバンドル名にエントリハッシュが入らないためで、これは想定内）；
      診断テキストを編集 → パネル内のリンクの `href` が即座に変化；閉じて開き直す → 下書きは破棄され自動計測値に戻る
- [ ] ページをリロード → ファイルもグラフも残っている（ローカル IndexedDB から復元）；Clear をクリックしてもう一度リロード → クリーンで何も残らない

上記の**太字の 3 つの核心グループ**（グラフ → コード、コード → グラフ、呼び出し箇所ジャンプ）はすでに自動化済みです。
インタラクションロジックを変更する際は、まず `node scripts/browser-verify.mjs` を実行してください — 次のセクションを参照。

## ブラウザ自動化受け入れ（実 Chrome + CDP）

jest + jsdom では「フラッシュするハイライトが実 rAF でフェードアウトするか」や「SVG ノードが実マウスで本当にヒットできるか」といった問題は捕捉できません（コミット `d0f0832` が直したのはまさにそのようなブラウザ限定のバグでした）。そこで 2 つ目の、実ブラウザのスクリプトがあります：ヘッドレス Chrome + ネイティブ CDP プロトコルで、**playwright / puppeteer に依存しません** — ローカルに Chrome か Chromium が入っていれば実行できます。

```bash
npm run export                  # まず dist/ を生成
node scripts/browser-verify.mjs # 47 アサーション（うち 16 は約束の表面 E/F/G）；すべて緑 => 終了コード 0
```

スクリプトは `dist/` 用の静的サーバを自分で起動し、`dist/_headers` のルールをすべてのレスポンスに逐語的に適用します（つまりスモークテストは本番の CSP そのもので走ります）。ポートが使用中のときは既存サービスを再利用しますが、その前に 2 つを検証します：そのポートで動いているものが本当にこのアプリケーションであること（判定基準は HTML 内のこのプロジェクトの Metro エントリスクリプトタグであって **`<title>` ではない** — タイトルを変えた途端に誤判定するからです）、そして配信されているバイト列が `dist/index.html` と完全一致すること。その後ヘッドレス Chrome を起動し、`fixtures/` の 3 ファイルを流し込み、**実マウスイベントで** SVG ノードとコードトークンをクリックして、項目ごとにアサートします：

| グループ                  | カバー範囲                                                                                                                                     |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Upload                    | 赤い致命エラーバーがない；グラフが描画される（ベースライン 45 ノード / 47 エッジ）                                                             |
| A グラフ → コード         | ファイルが切り替わり、`def` 行が完全に見える位置までスクロールし、ハイライト帯が `def` 行に乗る；フラッシュが出現 → ピーク → フェード → アンマウント；連打で再トリガー |
| B コード → グラフ         | 対象ノードが中央に来る（ずれ < 40px）かつ stroke が太くなる；コード → グラフ方向ではフラッシュ**しない**                                        |
| C ファイル横断の深いジャンプ | `shapes.py` から `utils.py:95` へ飛ぶ；スクロール量、ハイライト帯の位置、フラッシュがすべて正しい                                            |
| D 意味的クリック          | 呼び出し箇所をクリックすると呼び出し先が選択される；本体の中間行をクリックするとそれを包む関数が選択される                                      |
| 安定性                    | コンソールエラーなし、未捕捉のページ例外なし                                                                                                   |
| S 成果物の同一性          | 配信バイト列 == `dist/index.html` のバイト列（sha256 一致）；レスポンスヘッダが本当に `_headers` の CSP を運んでいる；成果物 HTML に絶対 URL がゼロ |
| E 約束の表面              | すべてのリクエストが同一オリジン / すべてのリクエストが GET / リクエストボディゼロ / 4xx・5xx なし / すべての 200 が `dist/` に実在するファイルに対応 / 動いているのが `dist` のあのエントリ JS / どの URL にもユーザーコンテンツなし / 本番 CSP 下で `securitypolicyviolation` ゼロ |
| F アイコン連鎖            | `<head>` が本当に注入済みアイコンリンク 4 つを含む；すべての href が `<img>` としてデコードできる（同一オリジン + CSP `img-src` + MIME がすべて正しい） |
| G フィードバックパネル    | トップバーの入口がパネルを開き、パネルが**本当に最前面に浮かぶ**（閉じるボタン中心のヒットテストがボタン自身）；「開く → 閉じる」の 1 往復でリクエストが**1 件も増えない**；診断ブロックがちょうど 8 行で i 行目がホワイトリストのフィールド i であり、`build` == 被テストのエントリハッシュの先頭 8 文字；件数がページに実際に描画されている数字と整合；`<a>` の数がゲートの期待値と一致し、Issues アンカーの `target`/`rel` が正しい |

任意の環境変数：

| 変数               | 既定値       | 用途                                                                                                                     |
| ------------------ | ------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `CODEMAP_PORT`     | `8099`       | 静的サーバのポート；使用中の場合は既存サービスを再利用（そのバイト列が `dist` と一致し、本当にこのアプリケーションであることを検証済み） |
| `CODEMAP_CDP_PORT` | `9333`       | Chrome リモートデバッグポート                                                                                             |
| `CHROME_PATH`      | 自動検出     | ブラウザ実行ファイルへのパス（Windows / macOS / Linux の一般的な場所をすべて試す）                                        |

スクリーンショット（`codemap-shots/01-initial.png` … `06-deep-crossfile.png`、`07-feedback-panel.png`）と JSON レポート（`codemap-verify-report.json`）はシステムの一時ディレクトリに書き込まれ、コミットされません。終了時、スクリプトは自分で起動したサーバをシャットダウンします。

## サイトアイコン

`public/icon.svg` が唯一の真実の源です：明るい紙の背景 + 抽象化されたコードグラフ — 青/黄/緑/紫（テーマのファイル色）の塗りつぶし角丸ノード 4 つを、テーマのアクセント色の太い丸端ストローク 3 本で結んだもの（旧「ノード + リンク」の骨格は保ち、グリッド、グロー、矢印、内部線は落としました）。`npm run icons` がこれを実 Chrome でラスタライズし、`favicon.ico`（16/32/48、PNG-in-ICO）、`apple-touch-icon.png`（180）、`icon-192.png`、`icon-512.png` を生成します — **すべてコミット済み**なので、export と CI の checks ジョブはブラウザなしで完全な `dist/` を作れます。`npm run export` の postexport ステップはまず `scripts/inject-html-head.mjs` を実行し、成果物 HTML の `<head>` に 4 つの `<link>` と 2 つの `<meta>` を書き込みます（同一オリジンの相対パス；冪等性のセンチネルは `data-codemap="icon"` なので、繰り返し実行してもタグが重なりません）。続いて `polish-dist.mjs` が自己チェックを行います — 注入された href も「絶対 URL ゼロ」ゲートの対象内であり、ゲートの外にある飛地ではありません。アイコンの色は `src/theme.ts` からしか取れません（`__tests__/icons.test.ts` がこの不変条件をロックしている）ので、テーマの色を変えればアイコンも追従します。ヘッドレス Chrome は `<link rel="icon">` を取得しないため、スモークテストは注入されたすべての href を `<img>` 経由で能動的に引きます（グループ F）。そしてそれらのリクエストはグループ E の約束の表面も通ります。

## 解析能力と限界

**エッジが描かれるもの**：ファイル内の直接呼び出し、ファイルをまたぐ `mod.func()` 呼び出し、`from m import f` の後の素の `f()`、`as` エイリアス付き import、相対 import、`self.method()` / `cls.method()`、`Cls.staticmethod()`、インスタンス化 `Cls(...)` → `__init__`、ネストした関数がそれを包む関数を呼ぶケース、再帰の自己ループ。

**エッジが付かない呼び出し箇所**は reason（`ambiguous` / `external` / `dynamic` / `unknown`）付きで記録され、UI 上はノードのバッジと上部の統計として表面化します。完全なルール、根拠、却下された代替案は [ADR-0002](docs/adr/0002-conservative-call-resolution.md) にあります。

その他の限界：

- 受け付けるのは `.py` / `.pyi` のテキストファイルのみ；1 ファイルあたり 1MB が上限で、超過分はスキップとして報告されます。
- 永続化はあなた自身のブラウザの中だけで起きます：セッション（全ファイル内容を含む）はローカル IndexedDB に書き込まれ、リロードで復元されます。サーバ側の保存はなく、サイトデータの消去が完全な削除です。
- 解析はブラウザのメインスレッド上でバッチ実行されます（1 バッチ 3 ファイル）— 数十ファイルなら瞬時に感じられますが、数千ファイルのリポジトリでは固まります。Web Worker は予約済みだがまだ有効化されていない最適化スロットです。
- 静的な構文解析のみ；アップロードされたコードは一切実行されません。

## テスト

3 層あり、すべて `npm test` で走ります：

| 層                             | ファイル                                                                                                                             | wasm が必要？                            |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------- |
| **純関数の単体テスト**         | `modules` / `imports` / `scope` / `layout` / `buildGraph` / `store` / `clickRanges` / `graphPaneMath` / `codeView` / `smoke`           | 不要（`treeLike` インターフェース経由の偽の構文木） |
| **コンポーネントとインタラクション** | `appFlow.test.tsx` / `topBar.test.ts` / `feedback.test.tsx`（カナリア + ホワイトリスト形状 + パネル描画）                        | 不要（store を事前に投入）               |
| **実 wasm フルチェーン**       | `parser.wasm.test.ts` / `imports.wasm.test.ts` / `e2e.wasm.test.tsx`                                                                  | 必要                                     |

`public/wasm/*.wasm` が存在しない場合、第 3 層は失敗するのではなく**丸ごとスキップ**されます（`describeWasm` ヘルパ）。したがって `--ignore-scripts` でインストールした場合でも、最初の 2 層は実行できます。すべてを走らせるには：先に `npm run copy-wasm`（通常の `npm install` は `postinstall` で既にやっています）。

`e2e.wasm.test.tsx` が実際の使用に最も近いものです：実 wasm が fixtures を解析 → `store.loadFiles` → `AppRoot` を描画 → 実際のクリック、という流れで、上記受け入れチェックリストの 2 つの核心ナビゲーション経路、不正ファイルの縮退、ファイル削除の同期をカバーします。

解析ルールを変更するときは、`fixtures/` の統計ベースライン（funcs 45 / edges 47 / unresolved 28）に注意してください。数字が動いたら、なぜ動いたのかを説明できなければなりません — テストを編集して済ませないこと。

`npm test` の外に第 4 の層があります：実ブラウザ受け入れ（`node scripts/browser-verify.mjs`、`npm test` には含まれません）。実 Chrome + rAF + ネイティブマウスイベント上で走り、jsdom では扱えないフラッシュのフェードアウトと SVG のヒットテストをカバーします；「ブラウザ自動化受け入れ」のセクションを参照。

## トラブルシューティング

**`[copy-wasm] 冒烟校验失败`（スモークチェック失敗）/ ページ上部の赤いエラーバー**

最も可能性が高いのは `web-tree-sitter` と言語 wasm の ABI が一致していないことです。両パッケージは `package.json` で完全固定されています（`web-tree-sitter` `0.27.0` + `@vscode/tree-sitter-wasm` `0.3.1`）；片方だけをアップグレードしないでください。アップグレード後は必ず `npm run copy-wasm` を再実行し、スモークチェックが通ることを確認してください。赤いエラーバーは `Language.load` が投げたエラーを逐語的に表示します — サイレントな縮退はありません。

**ページは開くがグラフが空 / `LinkError`**

`public/wasm/` の下に本当に 2 つの `.wasm` があるか確認してください。dev server も `expo export` も `public/` を同梱するので、パスは `/wasm/tree-sitter.wasm` です。

**ホイールでズームするとページ全体がスクロールする**

wheel リスナは `preventDefault` できるように**非パッシブ**（`passive: false`）でなければなりません。react-native-web の `onWheel` はそれができないため、`src/platform/web/domEvents.ts` で自前にネイティブイベントを購読しています。これを RN の `onWheel` に戻さないでください。

**`npm run export` が制限された環境で EPERM を報告する**

Expo はユーザーディレクトリに状態ファイルを書きます（`~/.expo/state.json`）。その書き込みがサンドボックス化されている環境では、`EXPO_HOME` をリポジトリ内に向けてください：

```powershell
$env:EXPO_NO_TELEMETRY = "1"; $env:CI = "1"; $env:EXPO_HOME = "$PWD\.expo-home"
npx expo export --platform web --output-dir dist
```

## リリースと運用

完全な手順、プラットフォームの落とし穴、ロールバック手順は [docs/ops-deployment.md](docs/ops-deployment.md) に記録されています。最も一般的な 2 つの操作：

- **公開を止める**：リポジトリ変数 `DEPLOY_ENABLED` を `false` に設定する。これが唯一のスイッチです — コードは消さず、ジョブは消さず、認証情報も消しません。
- **本番がまさにテストしたあのビルドだと確認する**：`npm run export` は最後に `dist/index.html` の sha256 を表示します；スモークテストの `S1` アサーションがサーバのバイト列を比較し、`check-deploy.mjs --dist=dist` が本番とローカル成果物を比較します。
